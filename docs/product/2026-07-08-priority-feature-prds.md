# RapperRank Priority Feature PRDs

这份文档只选当前最值得先做的 3 个功能。

筛选标准:

- 必须直接服务“说唱图鉴 + 评分平台 + 互动社区”
- 必须能提高回访
- 必须能在现有页面和数据基础上增量实现
- 必须能让“这网站很酷，我的 rapper 评分如何”这句感受变得更具体

---

## PRD 1: 我的评分档案

### Feature Goal

把用户留下的评分、喜爱度和收藏，转化成一个可见、可解释、可持续更新的个人审美档案。

### Why Now

当前用户已经能评分，但评分后的回报太弱。个人中心更像记录页，还不像“我的说唱判断主页”。

如果这一步不成立，后续社区功能会缺少稳定的个人资产基础。

### User

- 已完成 3 次以上评分的硬核说唱听众
- 对自己口味有表达欲，希望看见系统总结的人

### User Problem

- 我评了不少，但系统没有告诉我“我到底偏什么”
- 我想知道自己更喜欢哪类 Rapper、哪类厂牌、哪类风格
- 我希望我的判断是持续积累的，而不是一次性弹窗行为

### Core Value

让用户第一次明显感受到:

- 我的评分有沉淀
- 我的口味可以被总结
- 我继续评分会得到更完整的自我画像

### User Story

1. 用户进入个人中心。
2. 系统展示当前评分总数、收藏总数、最近评分记录。
3. 当用户评分达到阈值后，展示“我的评分档案”卡片。
4. 用户看到自己的风格偏好、维度倾向、喜爱度分布、偏爱厂牌或地域。
5. 用户产生“我再评几个看看画像会不会变化”的动机。

### Scope

#### In Scope

- 档案总览卡
- 评分数量里程碑反馈
- 维度倾向总结
- 风格标签总结
- 喜爱度分布
- 与社区均值的基础对比

#### Out Of Scope

- 对外公开主页
- 用户互相关注
- 长文自述
- AI 自动生成大段文案

### Functional Design

#### 1. 档案头部

展示:

- 总评分数
- 收藏数
- 最近一次评分时间
- 当前口味标签

口味标签可以先做成 2 到 4 个短标签，例如:

- Flow 优先
- 地下硬核偏好
- 旋律接受度高
- 厂牌导向明显

#### 2. 维度倾向

把用户所有评分聚合后，输出:

- 最重视的两个评分维度
- 最不敏感的一个评分维度
- 用户平均偏向 underground / balanced / mainstream

#### 3. 偏好画像

按现有 Rapper 数据可先输出:

- 最常高分的地域
- 最常高分的厂牌
- 最常高分的标签

#### 4. 社区对比

展示:

- 用户平均分与社区均分差值
- 用户最“高估”的 Rapper
- 用户最“低估”的 Rapper

#### 5. 评分进度反馈

在 3、10、20 次评分后给不同文案反馈:

- 3 次: 已开始形成判断
- 10 次: 口味画像初步稳定
- 20 次: 你已经有鲜明的说唱审美轮廓

### UI Notes

- 不能做成传统统计后台
- 更像“审美档案”而不是“数据报表”
- 可保留现有黑底高对比风格，但要让反馈更有仪式感

### Data Notes

优先复用现有数据:

- 用户评分记录
- 喜爱度
- Rapper 标签
- 厂牌归属
- 地域信息

### Success Metrics

- 档案页查看率
- 查看档案后的新增评分率
- 10 次评分达成率
- 7 日回访率

### Smallest Shippable Version

- 只在个人中心增加一个“我的评分档案”区域
- 先输出评分总数、口味标签、维度倾向、最常高分地域
- 暂不做公开分享

## PRD 2: 争议榜

### Feature Goal

把社区页从“静态榜单页”升级为“有表达张力的公共场景”。

### Why Now

当前社区页已经有榜单基础，但用户还缺少一个“我想进去看看大家到底怎么吵”的理由。

争议榜比评论区更轻，也更符合当前阶段。

### User

- 已经有基本说唱认知的人
- 对热门 Rapper、分歧 Rapper、立场差异有兴趣的人

### User Problem

- 只看高分榜不够刺激
- 我更想看哪些 Rapper 最容易引起分歧
- 我希望找到能激发我去打分的对象

### Core Value

把“社区”从静态展示变成判断碰撞空间。

### User Story

1. 用户进入社区页。
2. 用户看到默认综合榜，同时可切换到争议榜。
3. 用户发现某些 Rapper 社区意见极度分裂。
4. 用户点进详情页查看，并留下自己的评分。
5. 用户之后会回来观察争议排序是否变化。

### Scope

#### In Scope

- 争议榜 tab
- 最分裂 Rapper 列表
- 最有共识 Rapper 列表
- 我的评分与社区均分差值入口

#### Out Of Scope

- 评论区
- 辩论帖
- 用户互喷式互动
- 复杂举报审核系统

### Functional Design

#### 1. 排行类型

第一版建议至少支持:

- 综合榜
- 喜爱度榜
- 争议榜

#### 2. 争议计算

第一版不追求复杂建模，先用以下原则:

- 评分人数达到门槛后才进入争议计算
- 综合分标准差越高，争议越强
- 喜爱度与综合分出现明显错位时可作为额外排序信号

#### 3. 争议解释

每个条目最好有一行简短提示，例如:

- 社区意见高度分裂
- 喜爱度高于综合认可度
- 社区均分波动明显

#### 4. 导流动作

每个榜单条目都应引导用户:

- 去详情页
- 去补评分
- 去和社区做对比

### UI Notes

- 争议榜的语气不要太学术
- 可以偏有张力的命名，例如“最分裂”“最不统一”“爱恨分明”
- 但不要做成煽动性过强的娱乐八卦区

### Data Notes

所需基础数据:

- 评分人数
- 综合分
- 各维度评分分布
- 喜爱度均值与人数

### Success Metrics

- 社区页停留时长
- 争议榜点击率
- 从争议榜进入评分弹窗比例
- 社区页带来的新增评分数

### Smallest Shippable Version

- 在现有社区页新增“争议榜”切换
- 用综合分分布做最基础排序
- 支持点击进入详情页评分

## PRD 3: 今日三连评

### Feature Goal

给用户一个轻量、低门槛、带节奏感的日常回访理由。

### Why Now

当前首页随机进入详情页是好的探索入口，但还缺少“我今天来要完成什么”的任务感。

今日三连评可以在不增加复杂社交的前提下，给产品一个稳定的节奏器。

### User

- 有碎片时间的硬核听众
- 已经愿意评分，但不一定愿意长时间深逛的人

### User Problem

- 我偶尔会想逛，但没有明确目标
- 我希望系统给我一组值得评的对象
- 我希望评完之后得到一点即时反馈

### Core Value

把单次随机探索升级为一个可完成的小挑战。

### User Story

1. 用户进入首页或社区页。
2. 系统展示“今日三连评”卡片。
3. 用户看到当天主题，例如某个厂牌、某个城市、某类风格，或一组容易分裂的 Rapper。
4. 用户依次完成 3 个评分。
5. 完成后系统输出一句当日判断总结，并引导查看个人档案或社区对比。

### Scope

#### In Scope

- 每日主题卡
- 三个推荐 Rapper
- 完成进度显示
- 完成后的总结反馈

#### Out Of Scope

- 连续签到奖励
- 勋章体系
- 实物奖励
- 复杂任务中心

### Functional Design

#### 1. 主题生成

第一版主题来源建议优先使用现有内容结构:

- 同厂牌 3 人
- 同城市 3 人
- 同风格标签 3 人
- 社区争议高的 3 人

#### 2. 任务状态

用户可以看到:

- 今日主题名称
- 已完成 0/3、1/3、2/3、3/3
- 每个 Rapper 的完成状态

#### 3. 完成反馈

完成 3 个评分后输出:

- 今日偏好总结
- 与社区一致度或偏离度
- 跳转到“我的评分档案”或“争议榜”

#### 4. 页面入口

建议入口放在:

- 首页头部
- 社区页头部
- 个人中心中作为回访推荐

### UI Notes

- 这是轻挑战，不是重运营活动
- 文案要像“今天来判断这一组人”，而不是“来完成任务拿奖励”
- 完成反馈要有一点仪式感，但不要过度游戏化

### Data Notes

优先复用:

- Rapper 标签
- 厂牌归属
- 地域信息
- 当日用户评分记录

### Success Metrics

- 今日三连评点击率
- 任务完成率
- 单次会话评分数
- 次日回访率

### Smallest Shippable Version

- 每天固定生成一个 3 人主题
- 只展示完成进度和完成后的简短总结
- 暂不做连续天数和奖励系统

---

## Priority Recommendation

如果只能按顺序做，建议:

1. 先做“我的评分档案”
2. 再做“争议榜”
3. 再做“今日三连评”

原因:

- 档案解决个人沉淀
- 争议榜解决社区张力
- 三连评解决日常回访

这三者组合起来，刚好对应 RapperRank 未来最重要的三个动作:

- `留下判断`
- `看见自己`
- `进入社区`
